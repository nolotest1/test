## 🌐 2. UNIVERSAL LLM ROUTER & CONTEXT ENGINE

### Auto-Discovery & Routing
- **Discovery Probe:** `GET {base_url}/v1/models` (OpenAI-compatible fallback covers 90% of cloud/local APIs). Fallback paths: `/api/tags` (Ollama), `/v1beta/models` (Gemini), `/v1/models` (Anthropic).
- **Config Schema (`config/llm_endpoints.yaml`):** Hot-reloadable, unlimited endpoints. Fields: `id`, `base_url`, `api_key` (env-injected), `auto_discover: true`, `refresh_interval_min`, `fallback_chain: []`.
- **Router Interface:** `LLMRouter.chat(messages, system, options) → AsyncGenerator<Chunk> | FullResponse`. Normalizes requests/responses via adapter registry. Handles 429/503 with exponential backoff.
- **Mid-Chat Switch:** Preserves conversation history, memory state, and tool bindings. Adapts system prompt if capability mismatch occurs. UI indicator: `🔄 Switched to Provider/Model (Ctx: X/Y)`.

### Context Manager
- Sliding window with priority preservation: `system_prompt > recent_turns > critical_tool_calls > long_context`.
- Auto-summarization fallback when approaching model limit.
- Per-model token estimation (tiktoken-compatible + provider overrides).
- Real-time usage meter: warns at 75%/90%, auto-truncates or blocks at 100% (configurable).

## 🛠️ 3. DYNAMIC MULTI-FORMAT SKILL ENGINE

### Folder-Based Structure
```
agents/skills/{skill_name}/
├── SKILL.md | skill.yaml | main.py  (native format)
├── skill.py (optional helper)
└── requirements.txt (optional)
```

### Native Multi-Format Loading (Zero Wrappers)
- **Runtime Detection:** Scans skill folder → identifies format → delegates to adapter registry.
- **Supported Formats & Adapters:**
  - `NEXUS_NATIVE`: `SKILL.md` + YAML frontmatter
  - `OPENCLAW`: `skill.yaml` + instruction blocks
  - `LANGCHAIN`: `BaseTool` subclass in `.py`
  - `MCP`: `mcp.json` or JSON-RPC endpoint
  - `RAW_PYTHON`: `main.py` with `def run(context)`
- **On-Demand Injection:** Load prompt/code ONLY when agent selects it. LRU cache (max 10). Never preload all skills.

### Hybrid Execution Model
- **Sync Mode (Default):** Secure subprocess sandbox. Limits: CPU 50%, RAM 512MB, Timeout 30s. Structured stdout/stderr capture.
- **Daemon Mode (Long-Running):** Metadata flag `execution_mode: daemon`. Spawns background process → immediately returns `{task_id, pid, status: "running"}`. Enables real-time WebSocket log streaming (`/ws/skills/{id}/logs`), kill signal, auto-cleanup.
- **Approval Policy:** Tied to `risk_level` + `auto_approve` in manifest. Integrates with 3-mode UI toggle: 🚀 `FULL_AUTO` | ⚡ `SMART_APPROVAL` | 🛡️ `MANUAL_STEP`.

## 🌍 6. CROSS-PLATFORM & RUNTIME GUARANTEES

- **Path Handling:** `node:path` / `pathlib` exclusively. Dynamic resolution of `$HOME`, `$PREFIX`, temp dirs.
- **Termux Awareness:** Detect `process.env.TERMUX_VERSION`. Use `$PREFIX/bin/python3`. Avoid `systemd`/`prctl`. Fallback to JS-side timers or `timeout` for resource limits.
- **Process Management:** `child_process` / `subprocess` with `stdio: pipe`, `detached: true` for daemons, `process.kill()` with signal cleanup.
- **TLS/Network:** `undici`/`httpx` with system cert fallback. Support proxy/env vars. HTTPS-only for webhooks & external skill imports.
- **Performance:** UI render budget <16ms/frame. Skill listing <100ms. LLM discovery <200ms. Memory footprint <300MB idle.
